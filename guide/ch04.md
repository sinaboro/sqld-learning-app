## 04.1 | 서브쿼리

**서브쿼리**는 SQL 문 안에 들어 있는 또 하나의 SELECT 문이에요. 괄호로 감싸요.

| 기준 | 종류 |
|---|---|
| 위치 | 스칼라 서브쿼리 (SELECT 절, 값 하나), 인라인 뷰 (FROM 절, 테이블처럼), 중첩 서브쿼리 (WHERE·HAVING 절) |
| 반환 행 수 | 단일행 (=, >, < 등 사용), 다중행 (IN, ANY, ALL, EXISTS 사용), 다중 칼럼 |
| 메인쿼리와의 관계 | 비연관 서브쿼리 (혼자 실행 가능), 연관(상관) 서브쿼리 (메인쿼리 칼럼을 사용) |

```sql
-- 단일행 서브쿼리: 평균 급여보다 많이 받는 사원
SELECT ENAME, SAL FROM EMP WHERE SAL > (SELECT AVG(SAL) FROM EMP);
```

```sql
-- 다중행 서브쿼리: 부서별 최고 급여를 받는 사원 (IN, 다중 칼럼)
SELECT DEPTNO, ENAME, SAL FROM EMP
WHERE (DEPTNO, SAL) IN (SELECT DEPTNO, MAX(SAL) FROM EMP GROUP BY DEPTNO);
```

| 다중행 연산자 | 뜻 |
|---|---|
| IN | 결과 중 하나와 같으면 |
| > ANY (SOME) | 결과 중 **하나라도** 보다 크면 = 최솟값보다 크면 |
| > ALL | 결과 **모두**보다 크면 = 최댓값보다 크면 |
| EXISTS | 결과가 **한 건이라도 있으면** 참 |

```sql
-- 연관 서브쿼리 + EXISTS: 사원이 한 명이라도 있는 부서
SELECT D.DEPTNO, D.DNAME FROM DEPT D
WHERE EXISTS (SELECT 1 FROM EMP E WHERE E.DEPTNO = D.DEPTNO);
```

```sql
-- 연관 서브쿼리: 자기 부서 평균보다 많이 받는 사원
SELECT E.DEPTNO, E.ENAME, E.SAL FROM EMP E
WHERE E.SAL > (SELECT AVG(SAL) FROM EMP WHERE DEPTNO = E.DEPTNO);
```

```sql
-- 스칼라 서브쿼리(SELECT 절)와 인라인 뷰(FROM 절)
SELECT E.ENAME, (SELECT DNAME FROM DEPT D WHERE D.DEPTNO = E.DEPTNO) AS 부서명
FROM (SELECT * FROM EMP WHERE SAL >= 3000) E;
```

!> 단일행 연산자(=, > 등) 뒤의 서브쿼리가 **여러 행**을 돌려주면 오류가 나요. 스칼라 서브쿼리도 한 행·한 칼럼만 돌려줘야 합니다.

> 💡 **뷰(View)**는 SELECT 문을 이름 붙여 저장한 가상 테이블이에요. 장점: 독립성(테이블이 바뀌어도 응용 프로그램 영향 적음), 편리성(복잡한 질의를 단순하게), 보안성(필요한 칼럼만 보여 줌).

## 04.2 | 집합 연산자

두 SELECT 결과를 **위아래로** 합치거나 비교해요. 두 쿼리의 **칼럼 수와 자료형이 같아야** 합니다.

| 연산자 | 결과 | 중복 | 정렬 |
|---|---|---|---|
| UNION | 합집합 | **제거** | 정렬될 수 있음 |
| UNION ALL | 합집합 | **그대로** | 정렬 안 함 (가장 빠름) |
| INTERSECT | 교집합 | 제거 | |
| MINUS (SQL Server·SQLite: EXCEPT) | 차집합 | 제거 | |

```sql
-- UNION 과 UNION ALL 비교: 10번 부서 업무 + 20번 부서 업무
SELECT JOB FROM EMP WHERE DEPTNO = 10
UNION
SELECT JOB FROM EMP WHERE DEPTNO = 20;
SELECT COUNT(*) AS UNION_ALL_건수 FROM (SELECT JOB FROM EMP WHERE DEPTNO = 10 UNION ALL SELECT JOB FROM EMP WHERE DEPTNO = 20);
```

```sql
-- INTERSECT: 10번과 20번 부서에 모두 있는 업무 / EXCEPT(MINUS): 20번에만 있는 업무
SELECT JOB FROM EMP WHERE DEPTNO = 10 INTERSECT SELECT JOB FROM EMP WHERE DEPTNO = 20;
SELECT JOB FROM EMP WHERE DEPTNO = 20 EXCEPT SELECT JOB FROM EMP WHERE DEPTNO = 10;
```

> 💡 결과의 칼럼 이름은 **첫 번째 SELECT** 를 따르고, ORDER BY 는 **맨 마지막에 한 번만** 쓸 수 있어요.

## 04.3 | 그룹 함수

GROUP BY 로 그룹별 집계를 할 때, **소계·합계 행을 함께** 만들어 주는 함수예요. (오라클·SQL Server 지원, 이 앱의 SQLite 는 미지원이라 같은 결과를 UNION ALL 로 보여 줘요)

| 함수 | 만드는 집계 | GROUP BY ROLLUP(A, B) 예 |
|---|---|---|
| ROLLUP(A, B) | (A, B) + (A 소계) + (전체 합계) | **순서가 중요**, N 개 칼럼이면 N+1 단계 |
| CUBE(A, B) | 가능한 **모든 조합**: (A,B), (A), (B), 전체 | 2^N 가지 |
| GROUPING SETS(A, B) | **지정한 것만** 각각: (A), (B) | 순서 무관, 전체 합계 없음 |

```sql norun
-- 오라클: 부서별·업무별 급여 합계 + 부서 소계 + 전체 합계
SELECT DEPTNO, JOB, SUM(SAL) AS 합계
FROM EMP WHERE DEPTNO IN (10, 20)
GROUP BY ROLLUP(DEPTNO, JOB);
```

```sql
-- 위 ROLLUP 과 같은 결과 (소계 행의 JOB, 합계 행의 DEPTNO 는 NULL)
SELECT DEPTNO, JOB, SUM(SAL) AS 합계 FROM EMP WHERE DEPTNO IN (10, 20) GROUP BY DEPTNO, JOB
UNION ALL SELECT DEPTNO, NULL, SUM(SAL) FROM EMP WHERE DEPTNO IN (10, 20) GROUP BY DEPTNO
UNION ALL SELECT NULL, NULL, SUM(SAL) FROM EMP WHERE DEPTNO IN (10, 20)
ORDER BY 1 NULLS LAST, 2 NULLS LAST;
```

### GROUPING 함수

소계·합계 때문에 생긴 NULL 이면 **1**, 원래 데이터면 **0** 을 돌려줘요. CASE 와 함께 '소계', '합계' 글자를 붙일 때 씁니다.

```sql norun
SELECT CASE GROUPING(DEPTNO) WHEN 1 THEN '전체 합계' ELSE TO_CHAR(DEPTNO) END AS 부서,
       CASE GROUPING(JOB) WHEN 1 THEN '소계' ELSE JOB END AS 업무,
       SUM(SAL) AS 합계
FROM EMP GROUP BY ROLLUP(DEPTNO, JOB);
```

```sql norun
-- CUBE: (부서, 업무) + 부서별 + 업무별 + 전체 / GROUPING SETS: 부서별 + 업무별만
SELECT DEPTNO, JOB, SUM(SAL) FROM EMP GROUP BY CUBE(DEPTNO, JOB);
SELECT DEPTNO, JOB, SUM(SAL) FROM EMP GROUP BY GROUPING SETS(DEPTNO, JOB);
```

> 💡 **행 수 계산**: 10·20번 부서의 (부서, 업무) 조합은 6개예요. ROLLUP(DEPTNO, JOB) = 6 + 부서 소계 2 + 합계 1 = **9행**, GROUPING SETS(DEPTNO, JOB) = 부서 2 + 업무 4 = **6행**.

## 04.4 | 윈도우 함수

**윈도우 함수**는 행을 줄이지 않고, 각 행 옆에 **순위·누적합·앞뒤 행 값** 같은 계산 결과를 붙여 줘요.

```sql norun
함수() OVER ([PARTITION BY 칼럼] [ORDER BY 칼럼] [ROWS|RANGE BETWEEN 시작 AND 끝])
```

### 순위 함수

| 함수 | 같은 값 처리 | 예 (3000, 3000, 2975) |
|---|---|---|
| RANK | 같은 순위, 다음 순위는 **건너뜀** | 1, 1, 3 |
| DENSE_RANK | 같은 순위, 다음 순위 **이어짐** | 1, 1, 2 |
| ROW_NUMBER | 같은 값도 **다른 순위** | 1, 2, 3 |

```sql
SELECT ENAME, SAL,
       RANK() OVER (ORDER BY SAL DESC) AS RNK,
       DENSE_RANK() OVER (ORDER BY SAL DESC) AS DRNK,
       ROW_NUMBER() OVER (ORDER BY SAL DESC, ENAME) AS RN
FROM EMP WHERE DEPTNO = 20;
```

### 집계 함수 + PARTITION BY, 누적 합계

```sql
SELECT DEPTNO, ENAME, SAL,
       SUM(SAL) OVER (PARTITION BY DEPTNO) AS 부서합계,
       SUM(SAL) OVER (PARTITION BY DEPTNO ORDER BY SAL, ENAME
                      ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS 누적합
FROM EMP WHERE DEPTNO IN (10, 30);
```

> 💡 **ROWS** 는 물리적인 행 개수로, **RANGE** 는 ORDER BY 값의 범위로 창(window)을 정해요. ORDER BY 만 쓰고 범위를 생략하면 `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` 라서 **같은 값을 가진 행은 함께 더해져요.**

```sql
-- 범위를 생략하면 RANGE: 급여 1250 인 두 사람은 누적합이 같다
SELECT ENAME, SAL, SUM(SAL) OVER (ORDER BY SAL) AS RANGE_누적 FROM EMP WHERE DEPTNO = 30;
```

### 행 순서 함수

| 함수 | 뜻 |
|---|---|
| FIRST_VALUE / LAST_VALUE | 창의 첫 / 마지막 행 값 |
| LAG(칼럼, n) / LEAD(칼럼, n) | n 행 **앞** / **뒤** 의 값 (기본 1) |

```sql
SELECT ENAME, HIREDATE, SAL,
       LAG(SAL) OVER (ORDER BY HIREDATE) AS 이전입사자급여,
       LEAD(ENAME) OVER (ORDER BY HIREDATE) AS 다음입사자,
       FIRST_VALUE(ENAME) OVER (ORDER BY HIREDATE) AS 첫입사자
FROM EMP WHERE DEPTNO = 10;
```

### 비율 함수

| 함수 | 뜻 |
|---|---|
| RATIO_TO_REPORT(칼럼) | 전체 합에서 차지하는 비율 (오라클) |
| PERCENT_RANK() | (순위 - 1) / (전체 행 수 - 1), 0 ~ 1 |
| CUME_DIST() | 현재 행 이하 값의 누적 비율 |
| NTILE(n) | 전체를 n 개 그룹으로 나눈 번호 |

```sql
SELECT ENAME, SAL,
       ROUND(PERCENT_RANK() OVER (ORDER BY SAL), 2) AS PR,
       ROUND(CUME_DIST() OVER (ORDER BY SAL), 2) AS CD,
       NTILE(2) OVER (ORDER BY SAL) AS 그룹,
       ROUND(SAL * 1.0 / SUM(SAL) OVER (), 3) AS 비율          -- RATIO_TO_REPORT(SAL) OVER () 와 같음
FROM EMP WHERE DEPTNO = 20;
```

## 04.5 | TOP-N 쿼리

"급여 상위 3명"처럼 **위에서 N 개만** 꺼내는 쿼리예요. DBMS 마다 방법이 달라요.

| 방법 | DBMS | 예 |
|---|---|---|
| ROWNUM | 오라클 | WHERE ROWNUM <= 3 |
| TOP (N) | SQL Server | SELECT TOP(3) … |
| FETCH FIRST N ROWS ONLY | 표준 (오라클 12c+) | ORDER BY … FETCH FIRST 3 ROWS ONLY |
| LIMIT N | MySQL, PostgreSQL, SQLite | ORDER BY … LIMIT 3 |
| ROW_NUMBER() | 윈도우 함수 (공통) | 인라인 뷰에서 순번 후 WHERE RN <= 3 |

!> 오라클 ROWNUM 은 **ORDER BY 보다 먼저** 매겨져요. 그래서 정렬된 상위 N 개를 얻으려면 **인라인 뷰에서 먼저 정렬**한 뒤 바깥에서 ROWNUM 을 걸어야 합니다. 또 `ROWNUM = 2` 나 `ROWNUM > 1` 은 결과가 나오지 않아요(1번이 없으면 2번도 생기지 않음).

```sql norun
-- 오라클: 잘못된 예 (아무 3명을 뽑은 뒤 정렬)
SELECT ENAME, SAL FROM EMP WHERE ROWNUM <= 3 ORDER BY SAL DESC;
-- 오라클: 올바른 예 (정렬 먼저, 그다음 3명)
SELECT * FROM (SELECT ENAME, SAL FROM EMP ORDER BY SAL DESC) WHERE ROWNUM <= 3;
```

```sql
-- 공통 방법: ROW_NUMBER 로 순번을 매기고 바깥에서 거르기
SELECT ENAME, SAL FROM (
  SELECT ENAME, SAL, ROW_NUMBER() OVER (ORDER BY SAL DESC, ENAME) AS RN FROM EMP
) WHERE RN <= 3;
```

```sql
-- 공동 순위까지 포함하려면 RANK (FETCH FIRST 3 ROWS WITH TIES 와 같은 효과)
SELECT ENAME, SAL FROM (SELECT ENAME, SAL, RANK() OVER (ORDER BY SAL DESC) AS R FROM EMP) WHERE R <= 2;
```

+ TOP(3)

+ 인라인 뷰에서 ORDER BY 한 뒤 바깥에서 ROWNUM <= N

@end

## 04.6 | 계층형 질의와 셀프 조인

### 셀프 조인

같은 테이블을 **별칭을 다르게** 붙여 두 번 쓰는 조인이에요. 사원과 관리자처럼 자기 참조 관계에 씁니다.

```sql
SELECT W.EMPNO, W.ENAME AS 사원, M.ENAME AS 관리자
FROM EMP W LEFT OUTER JOIN EMP M ON W.MGR = M.EMPNO
WHERE W.DEPTNO = 10;
```

### 계층형 질의 (오라클 CONNECT BY)

조직도처럼 **위아래 관계(트리)** 를 따라 내려가며 조회해요.

| 구문 | 뜻 |
|---|---|
| START WITH 조건 | 시작(루트) 행 |
| CONNECT BY PRIOR 자식 = 부모 | **PRIOR 쪽이 부모 → 순방향** (위에서 아래로) |
| LEVEL | 깊이 (루트 = 1) |
| CONNECT_BY_ISLEAF | 자식이 없으면 1 |
| SYS_CONNECT_BY_PATH(칼럼, '/') | 루트부터의 경로 |
| ORDER SIBLINGS BY | 같은 레벨(형제)끼리 정렬 |

```sql norun
SELECT LEVEL, LPAD(' ', 2 * (LEVEL - 1)) || ENAME AS 조직도, EMPNO, MGR
FROM EMP
START WITH MGR IS NULL                 -- KING 부터
CONNECT BY PRIOR EMPNO = MGR           -- 부모(PRIOR)의 EMPNO = 자식의 MGR → 아래로
ORDER SIBLINGS BY ENAME;
```

> 💡 `CONNECT BY PRIOR MGR = EMPNO` 처럼 바꾸면 **역방향**(자식 → 부모, 아래에서 위로)이에요. "PRIOR 가 붙은 칼럼이 이전 행"이라고 기억하세요.

```sql
-- 같은 트리를 표준 SQL 재귀 CTE 로 (WITH RECURSIVE: 이 앱에서 실행 가능)
WITH RECURSIVE T (LVL, ENAME, EMPNO, PATH) AS (
  SELECT 1, ENAME, EMPNO, ENAME FROM EMP WHERE MGR IS NULL
  UNION ALL
  SELECT T.LVL + 1, E.ENAME, E.EMPNO, T.PATH || '/' || E.ENAME
  FROM EMP E JOIN T ON E.MGR = T.EMPNO
)
SELECT LVL AS 레벨, LPAD(' ', 2 * (LVL - 1)) || ENAME AS 조직도, PATH AS 경로 FROM T ORDER BY PATH;
```

- 방향 없음

- 0
+ 1
- NULL
- -1
= 루트가 LEVEL 1, 그 자식이 2 예요.
? 같은 레벨의 형제 행끼리 정렬하는 구문은?
- ORDER BY LEVEL
+ ORDER SIBLINGS BY
- GROUP BY LEVEL
- CONNECT BY ORDER
= ORDER SIBLINGS BY 는 계층 구조를 유지하며 형제끼리 정렬해요.
? 자식이 없는 행(잎)이면 1 을 돌려주는 것은?
- LEVEL

= CONNECT_BY_ISLEAF 는 리프 노드에서 1 이에요.

## 04.7 | PIVOT 절과 UNPIVOT 절

- **PIVOT**: 행 값을 **열로** 돌려 세워요. (업무별 행 → 부서를 열로)
- **UNPIVOT**: 열을 **행으로** 내려요.

```sql norun
-- 오라클 PIVOT: 업무별로 부서 10·20·30 의 급여 합계를 열로
SELECT * FROM (SELECT JOB, DEPTNO, SAL FROM EMP)
PIVOT (SUM(SAL) FOR DEPTNO IN (10 AS D10, 20 AS D20, 30 AS D30));
```

```sql
-- 같은 결과를 CASE 로 (모든 DBMS 에서 가능)
SELECT JOB,
       SUM(CASE WHEN DEPTNO = 10 THEN SAL END) AS D10,
       SUM(CASE WHEN DEPTNO = 20 THEN SAL END) AS D20,
       SUM(CASE WHEN DEPTNO = 30 THEN SAL END) AS D30
FROM EMP GROUP BY JOB ORDER BY JOB;
```

```sql norun
-- 오라클 UNPIVOT: D10, D20, D30 열을 (부서, 급여) 행으로
SELECT * FROM PIVOT_RESULT
UNPIVOT (SAL FOR DEPTNO IN (D10 AS 10, D20 AS 20, D30 AS 30));
```

> 💡 PIVOT 은 FOR 절에 지정하지 않은 칼럼(위의 JOB)을 기준으로 **자동으로 GROUP BY** 해요. 그래서 인라인 뷰로 필요한 칼럼만 남겨 두는 것이 중요합니다. UNPIVOT 은 NULL 인 값을 기본으로 **빼고** 보여 줘요(INCLUDE NULLS 로 포함 가능).

@quiz
? 행으로 된 값을 열로 바꾸는 구문은?
+ PIVOT
- UNPIVOT
- ROLLUP
- CUBE
= PIVOT 은 행 → 열, UNPIVOT 은 열 → 행이에요.

- 무시된다
+ 자동으로 GROUP BY 기준이 된다
- 오류가 난다
- 마지막 열이 된다
= 남은 칼럼 기준으로 자동 그룹화돼서, 인라인 뷰로 칼럼을 골라 두는 게 좋아요.
@end

## 04.8 | 정규 표현식

**정규 표현식**은 문자열의 **패턴**을 표현하는 방법이에요. 오라클은 REGEXP_ 로 시작하는 함수를 제공해요.

| 패턴 | 뜻 | 패턴 | 뜻 |
|---|---|---|---|
| . | 아무 글자 하나 | ^ / $ | 문자열 시작 / 끝 |
| * / + / ? | 0번 이상 / 1번 이상 / 0~1번 | {n} {n,m} | n번 / n~m번 |
| [abc] / [^abc] | 괄호 안 글자 하나 / 제외 | \d / \w / \s | 숫자 / 문자·숫자·_ / 공백 |
| a\|b | a 또는 b | ( ) | 묶음(그룹) |

| 함수 | 하는 일 |
|---|---|
| REGEXP_LIKE(문자열, 패턴) | 패턴과 맞으면 참 (WHERE 절 조건) |
| REGEXP_SUBSTR(문자열, 패턴) | 패턴에 맞는 부분 꺼내기 |
| REGEXP_REPLACE(문자열, 패턴, 바꿀값) | 패턴에 맞는 부분 바꾸기 |
| REGEXP_INSTR(문자열, 패턴) | 패턴 위치 |
| REGEXP_COUNT(문자열, 패턴) | 패턴 개수 |

```sql
-- 이름이 A 또는 S 로 시작하고 N 으로 끝나지 않는 사원 (오라클: WHERE REGEXP_LIKE(ENAME, '^[AS]'))
SELECT ENAME FROM EMP WHERE REGEXP_LIKE(ENAME, '^[AS]') AND NOT REGEXP_LIKE(ENAME, 'N$');
```

```sql
SELECT REGEXP_SUBSTR('주문번호 A-2026-0042', '[0-9]+') AS 처음숫자,
       REGEXP_REPLACE('010-1234-5678', '[0-9]{4}$', '****') AS 가리기,
       REGEXP_COUNT('banana', 'an') AS 개수,
       REGEXP_INSTR('SQL Expert', '[A-Z][a-z]') AS 위치
FROM DUAL;
```

@quiz
? 정규 표현식 '^S' 의 뜻은?

- S 를 포함하지 않는다

= ^ 는 문자열의 시작이에요. 끝은 $ 예요.

- REGEXP_SUBSTR
+ REGEXP_LIKE
- REGEXP_REPLACE
- REGEXP_COUNT
= REGEXP_LIKE 는 참·거짓 조건이라 WHERE 절에 써요.

- 2
+ 3
- 6
= banana 에 a 가 3번 나와요.
@end

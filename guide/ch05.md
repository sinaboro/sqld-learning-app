## 05.1 | DML

DML 은 테이블의 **데이터를 바꾸는** 명령이에요. (SELECT 를 포함하기도 해요)

```sql
-- INSERT: 칼럼을 지정해서 / 모든 칼럼 순서대로
INSERT INTO DEPT (DEPTNO, DNAME, LOC) VALUES (50, 'DESIGN', 'SEOUL');
INSERT INTO DEPT VALUES (60, 'QA', 'BUSAN');
SELECT * FROM DEPT WHERE DEPTNO >= 50;
```

```sql
-- 서브쿼리로 여러 행을 한 번에 INSERT
CREATE TABLE EMP_SALES AS SELECT * FROM EMP WHERE 1 = 2;     -- 구조만 복사 (행 없음)
INSERT INTO EMP_SALES SELECT * FROM EMP WHERE JOB = 'SALESMAN';
SELECT EMPNO, ENAME, JOB FROM EMP_SALES;
```

```sql
-- UPDATE: WHERE 로 고칠 행을 정한다 (WHERE 가 없으면 모든 행!)
UPDATE EMP SET SAL = SAL * 1.1 WHERE DEPTNO = 10;
SELECT ENAME, SAL FROM EMP WHERE DEPTNO = 10;
```

```sql
-- DELETE: WHERE 로 지울 행을 정한다
DELETE FROM EMP WHERE ENAME = 'MILLER';
SELECT COUNT(*) AS 남은인원 FROM EMP;
```

### MERGE: 있으면 UPDATE, 없으면 INSERT

```sql norun
MERGE INTO DEPT D
USING (SELECT 40 AS DEPTNO, 'OPS' AS DNAME, 'SEOUL' AS LOC FROM DUAL
       UNION ALL SELECT 70, 'AI', 'PANGYO' FROM DUAL) S
ON (D.DEPTNO = S.DEPTNO)
WHEN MATCHED THEN UPDATE SET D.DNAME = S.DNAME, D.LOC = S.LOC          -- 40번은 있으니 수정
WHEN NOT MATCHED THEN INSERT (DEPTNO, DNAME, LOC) VALUES (S.DEPTNO, S.DNAME, S.LOC);  -- 70번은 새로
```

```sql
-- 위 MERGE 와 같은 결과 (SQLite 의 UPSERT 문법)
INSERT INTO DEPT (DEPTNO, DNAME, LOC) VALUES (40, 'OPS', 'SEOUL'), (70, 'AI', 'PANGYO')
ON CONFLICT (DEPTNO) DO UPDATE SET DNAME = excluded.DNAME, LOC = excluded.LOC;
SELECT * FROM DEPT WHERE DEPTNO IN (40, 70);
```

> 💡 오라클에서 DML 은 **자동 커밋되지 않아요.** COMMIT 해야 확정되고, 다른 사용자도 볼 수 있어요. (SQL Server 는 기본이 자동 커밋)

- 아무 행도 바뀌지 않는다
= WHERE 가 없으면 테이블의 모든 행이 대상이에요.
? 조건에 맞으면 UPDATE, 없으면 INSERT 하는 DML 은?
- UPSERT
+ MERGE
- REPLACE
- UNION
= 오라클·표준의 MERGE 문이에요.

- EMP 의 모든 행이 복사된다
+ 구조만 복사되고 행은 없다
- 오류가 난다
- 제약조건까지 모두 복사된다
= 조건이 항상 거짓이라 행 없이 칼럼 구조만 만들어져요. (NOT NULL 외 제약조건은 복사 안 됨)
@end

## 05.2 | TCL

**TCL** 은 트랜잭션을 **확정하거나 취소**하는 명령이에요.

| 명령 | 하는 일 |
|---|---|
| COMMIT | 지금까지의 변경을 **확정** (영구 저장) |
| ROLLBACK | 마지막 COMMIT 이후 변경을 **취소** |
| SAVEPOINT 이름 | 중간 저장점 만들기 |
| ROLLBACK TO 이름 | 저장점까지만 되돌리기 |

```sql
BEGIN;                                           -- (SQLite) 트랜잭션 시작. 오라클은 첫 DML 에서 자동 시작
UPDATE EMP SET SAL = 9999 WHERE ENAME = 'SMITH';
SAVEPOINT SP1;
DELETE FROM EMP WHERE ENAME = 'SMITH';
ROLLBACK TO SP1;                                 -- DELETE 만 취소
SELECT ENAME, SAL FROM EMP WHERE ENAME = 'SMITH';
ROLLBACK;                                        -- UPDATE 까지 모두 취소
SELECT ENAME, SAL FROM EMP WHERE ENAME = 'SMITH';
```

> 💡 **오라클 자동 커밋**: DDL(CREATE, ALTER, DROP, TRUNCATE)이나 DCL 을 실행하면 그 전의 DML 이 **자동으로 커밋**돼요. 정상 종료 시에도 커밋, 비정상 종료 시에는 롤백됩니다. SQL Server 는 DDL 도 트랜잭션 안에서 롤백할 수 있어요.

@quiz
? 마지막 COMMIT 이후의 변경을 모두 취소하는 명령은?
- COMMIT
+ ROLLBACK
- SAVEPOINT
- REVOKE
= ROLLBACK 은 확정되지 않은 변경을 모두 되돌려요.
? 오라클에서 UPDATE 후 CREATE TABLE 을 실행하고 ROLLBACK 하면 UPDATE 는?
- 취소된다
+ 이미 커밋되어 취소되지 않는다
- 오류가 난다
- 절반만 취소된다
= DDL 실행 시 앞의 DML 이 자동 커밋돼요.
? SAVEPOINT A 다음에 DELETE, 그 뒤 ROLLBACK TO A 를 하면?
+ DELETE 만 취소된다
- 모든 변경이 취소된다
- 아무것도 취소되지 않는다
- 트랜잭션이 커밋된다
= 저장점 이후의 변경만 되돌려요.
@end

## 05.3 | DDL

DDL 은 테이블 같은 **데이터베이스 객체의 구조**를 만들고 바꾸는 명령이에요.

```sql
CREATE TABLE MEMBER (
  MEMBER_ID   INTEGER      PRIMARY KEY,                 -- 기본키: NOT NULL + UNIQUE
  EMAIL       VARCHAR(50)  NOT NULL UNIQUE,             -- 비어 있으면 안 되고 중복 불가
  AGE         INTEGER      CHECK (AGE >= 0),            -- 값의 범위 검사
  GRADE       VARCHAR(10)  DEFAULT 'BASIC',             -- 값을 안 주면 기본값
  DEPTNO      INTEGER      REFERENCES DEPT(DEPTNO)      -- 외래키
);
INSERT INTO MEMBER (MEMBER_ID, EMAIL, AGE) VALUES (1, 'kim@ex.com', 20);
SELECT * FROM MEMBER;
```

### 제약조건

| 제약조건 | 뜻 |
|---|---|
| PRIMARY KEY | 기본키. **NOT NULL + UNIQUE**, 테이블당 하나 |
| UNIQUE | 중복 불가 (**NULL 은 허용**) |
| NOT NULL | NULL 불가 |
| CHECK | 조건을 만족하는 값만 허용 |
| FOREIGN KEY | 다른 테이블의 PK 참조, 참조 무결성 보장 |
| DEFAULT | 값이 없을 때 기본값 (엄밀히는 제약조건이 아님) |

```sql error
INSERT INTO MEMBER (MEMBER_ID, EMAIL, AGE) VALUES (2, 'lee@ex.com', -5);   -- CHECK 위반
```

### 외래키 삭제 옵션

| 옵션 | 부모 행을 지우면 |
|---|---|
| (기본, RESTRICT / NO ACTION) | 자식이 있으면 **삭제 불가** |
| ON DELETE CASCADE | 자식 행도 **함께 삭제** |
| ON DELETE SET NULL | 자식의 FK 를 **NULL 로** |

### ALTER, RENAME, DROP, TRUNCATE

```sql
ALTER TABLE MEMBER ADD PHONE VARCHAR(20);                -- 칼럼 추가
ALTER TABLE MEMBER RENAME COLUMN PHONE TO TEL;            -- 칼럼 이름 변경
ALTER TABLE MEMBER RENAME TO CUSTOMER;                    -- 테이블 이름 변경
SELECT * FROM CUSTOMER;
```

```sql norun
-- 오라클 전용 / 표준 문법 (이 앱의 SQLite 는 일부 미지원)
ALTER TABLE CUSTOMER MODIFY (TEL VARCHAR(30) NOT NULL);   -- 칼럼 속성 변경 (SQL Server: ALTER COLUMN)
ALTER TABLE CUSTOMER DROP COLUMN TEL;                     -- 칼럼 삭제
ALTER TABLE CUSTOMER ADD CONSTRAINT CK_AGE CHECK (AGE < 150);
TRUNCATE TABLE CUSTOMER;                                  -- 모든 행 삭제 (구조는 남김)
DROP TABLE CUSTOMER;                                      -- 테이블 자체 삭제
```

| 구분 | DELETE | TRUNCATE | DROP |
|---|---|---|---|
| 종류 | DML | DDL | DDL |
| 지우는 것 | 행 (WHERE 가능) | **모든 행** | **테이블 자체** (구조까지) |
| 롤백 | 가능 | 불가 (자동 커밋) | 불가 (자동 커밋) |
| 저장 공간 | 그대로 유지 | 초기화 (반납) | 모두 반납 |
| 속도 | 느림 (한 행씩 로그) | 빠름 | 빠름 |

## 05.4 | DCL

**DCL** 은 사용자에게 **권한을 주고 빼앗는** 명령이에요.

```sql norun
CREATE USER SCOTT2 IDENTIFIED BY tiger;            -- 사용자 만들기 (오라클)
GRANT CREATE SESSION, CREATE TABLE TO SCOTT2;      -- 시스템 권한: 접속, 테이블 생성
GRANT SELECT, INSERT ON EMP TO SCOTT2;             -- 객체 권한: EMP 테이블 조회·입력
GRANT SELECT ON EMP TO SCOTT2 WITH GRANT OPTION;   -- 받은 권한을 다른 사람에게 줄 수 있게
REVOKE INSERT ON EMP FROM SCOTT2;                  -- 권한 회수
```

| 구분 | 예 |
|---|---|
| 시스템 권한 | CREATE SESSION, CREATE TABLE, CREATE USER … |
| 객체 권한 | 특정 객체에 대한 SELECT, INSERT, UPDATE, DELETE, ALTER, REFERENCES … |

### WITH GRANT OPTION vs WITH ADMIN OPTION

| 옵션 | 대상 | 회수할 때 |
|---|---|---|
| WITH GRANT OPTION | **객체 권한** | A → B → C 로 준 뒤 A 가 B 의 권한을 회수하면 **C 의 권한도 함께 회수** |
| WITH ADMIN OPTION | **시스템 권한** | B 의 권한을 회수해도 **C 의 권한은 남음** |

### ROLE: 권한 묶음

권한을 사용자마다 하나씩 주면 관리가 힘들어요. **ROLE** 에 권한을 모아 두고 ROLE 을 부여하면 편합니다.

```sql norun
CREATE ROLE APP_USER;
GRANT CREATE SESSION, SELECT ANY TABLE TO APP_USER;
GRANT APP_USER TO SCOTT2, KIM;                     -- 여러 사용자에게 한 번에
```

> 💡 오라클이 미리 만들어 둔 ROLE: **CONNECT**(접속 관련), **RESOURCE**(테이블 등 객체 생성 관련), **DBA**(모든 권한).
